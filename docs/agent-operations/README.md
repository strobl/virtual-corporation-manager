# Company and member guidance

Start with [your company](company-management.md): create its identity, add humans and AI agents, and keep their responsibilities and relationships understandable. [Members and responsibilities](members-and-responsibilities.md) explains roles, shared membership and reporting. Use the release-specific [first-company guide](../first-company.md) for installation and the [corporation-management contract](../product/corporation-management.md) for the product model.

Company setup needs a name and offers an optional purpose. Templates, runtime connections and execution tasks are optional. The existing [Time Tracker](../time-tracker.md) keeps its behavior and data. A configured member or reporting line does not automatically execute work, book hours or establish a completed result.

## Optional role and workflow library

The full role prompts, operating contract and Product Studio materials below serve deliberately chosen workflows. They are not the default company setup. Use the [Product Studio guide](../product-studio.md) for that specialized example and its platform, runtime, QA and owner-review requirements.

## Preserved content provenance

These shipped role documents, full prompts, operating contract and help use the current VCM product name. The [branding adaptation receipt](branding-receipt.json) records their original and adapted hashes. Role IDs, authority limits, job package identifiers, acceptance criteria and the frozen oracle are preserved.

The [original import receipt](import-receipt.json) and [integration manifest](product-studio.integration.json) retain the accepted source identities and hashes. Those hashes describe the original imported bytes, available in the repository revision identified by the adaptation receipt; they do not claim to hash the current adapted copies. The company charter's original source path is retained as provenance.

Use the current [first-company guide](../first-company.md) and [support instructions](../support.md). The [naming contract](../branding.md) defines the remaining technical compatibility names.

The separate `product-adaptation-receipt.json` records the company-management documentation delta after the alpha.6 naming adaptation. The branding receipt remains a historical intermediate record; its adapted hashes do not identify a subsequently edited help file. Original imports, role authority, criteria, oracle and execution evidence remain unchanged.
