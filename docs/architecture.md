# Architecture

VCM — Virtual Corporation Manager is one TypeScript application for one local operator. A Node.js process serves a bundled React console on `127.0.0.1` and opens a SQLite workspace. Company setup, organization editing, recorded work and the Time Tracker require no account, network, hosted database, billing service or telemetry.

This describes the current `0.1.0-alpha.6` review candidate. The [system architecture](system-architecture.md) maps its three core containers, components, persisted data and execution flows to source. [Architecture for contributors](developer-architecture.md) explains the domain and change workflow; [acceptance evidence](acceptance.md) records verification separately.

The browser submits typed configuration commands to the local runtime. Domain validation produces a persisted preview at a specific workspace revision. Explicit confirmation applies that exact preview and its audit receipt in one transaction. Replaying confirmation is idempotent; intervening configuration or time writes invalidate stale previews. Supported undo is version-aware and does not reverse an external action. An uncertain Apply receipt survives browser reload for explicit retry. See the [workspace store](../src/db/store.ts), [domain model](../src/domain/model.ts) and [browser recovery](../src/web/change-recovery.ts).

SQLite schema 5 holds organization, changes, work, execution receipts, workflow artifact bytes and a separate delivery-hours ledger. Time writes atomically persist the entry, captured calculation basis, history and request receipt while advancing the shared workspace revision. Totals use integer tenths of a human-equivalent hour. Configuration replacement preserves the time and execution ledgers; elapsed runtime, accepted output and booked hours are separate facts. See the [data model](data-model.md) and [Time Tracker](time-tracker.md).

Creating an agent stores its role and assignments; execution requires an explicit task or job. The optional individual-task queue runs one task at a time with at most 20 outstanding requests; its Codex route returns read-only text output. The fixed PS-001 company workflow runs five roles sequentially in separate workspace-write sessions, with one active job and at most three active-plus-queued jobs total. Start and Retry enforce the same admission limit. These queues are separate, so one individual task can run alongside one workflow. Codex uses the operator's installed CLI and provider access; experimental Buzz and Slack routes have additional prerequisites. See [integrations](integrations.md).

PS-001 captures the company, five role identities, named acceptance owner and content/input hashes. A prerequisite check precedes model dispatch. Runtime stages create actual files; a fixed sandboxed Python oracle and a different QA session inspect the captured candidate. Successful handoff leaves an explicit owner decision pending. The ready ZIP is sealed with frozen pre-decision provenance, SHA-256 and byte length; a new accept/reject decision records that exact digest. Downloads remain byte-identical after review and restore. Historical decisions without a bundle hash remain unbound; VCM does not manufacture past attestations. The [workflow contract](product-studio.md) and [workflow service](../src/jobs/service.ts) describe the bounded route.

The runtime owns an exclusive workspace process lock. Its [HTTP boundary](../src/server/index.ts) checks Host, Origin, cross-site requests, asset paths and a random per-process mutation capability. Trusted local processes can retrieve that capability from the session endpoint; it is not a shared-user authentication system. LAN hosting and tunnels are outside the supported deployment model. Data and backups are plaintext with local file permissions; runtime sandboxes restrict writes without promising full read isolation. See [security](../SECURITY.md).

Full SQLite backup/restore preserves configuration, hours, execution evidence and replay receipts together, validating migrations and data before replacement. Definition JSON is configuration only; time JSON is an inspectable ledger export. Completed workflow files survive without their disposable stage directories. Interrupted provider work is not automatically replayed on restart. Recovery commands are in the [developer quickstart](developer-quickstart.md#export-and-recovery).

The package uses Node's built-in `node:sqlite`; supported engines are Node 24.14+ within 24.x and Node 26.x. The local core and Time Tracker support macOS, Linux and Windows. Optional company-workflow checks additionally require Python 3.8+ and a working macOS/Linux Codex sandbox; native Windows is unsupported for that route. Source, configured CI and a built archive each need their own verification before a release claim.
